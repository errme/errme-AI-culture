# 前台 / 后台登录分离方案（双页面 · 双接口 · 双 Token）

> 目标：**前端登录就是前台，后端登录就是后台，且两套 Token 不同**——前台登录绝不获得后台权限，
> 前台 Token 也不能用于后台接口。

## 一、总体设计

| 维度 | 前台（用户端） | 后台（管理端） |
|---|---|---|
| 登录页面 | `/static/auth/login.html`（文件夹 1 样式） | `/static/auth/admin-login.html`（独立页面） |
| 入口 | 站内「登录」链接 / `/login` | `/toLogin` → 自动跳转后台登录页 |
| 登录接口 | `POST /api/auth/login` | `POST /api/auth/admin/login` |
| 账号要求 | 任意启用账号 | **必须拥有「管理员」角色**，否则直接拒绝 |
| Token 密钥 | `app.jwt.front-secret` | `app.jwt.admin-secret`（另一套密钥） |
| Token 声明 | `scope=front`、`userType=front` | `scope=admin`、`userType=admin` |
| 有效期 | `front-expire-hours`（默认 24h） | `admin-expire-hours`（默认 8h） |
| 浏览器存储 | `localStorage.culture_front_token` | `localStorage.culture_admin_token` |
| 服务端会话 | 只桥接 `loginUserName/loginUserId`（供前台 Thymeleaf 页面读登录人） | 建立完整 Spring Security 会话（含角色/权限），后台页面沿用 Session |
| 当前用户接口 | `GET /api/auth/me` | `GET /api/auth/admin/me` |
| 退出接口 | `POST /api/auth/logout` | `POST /api/auth/admin/logout` |

两套 Token 用**不同密钥 + scope 声明双重校验**：
即使把前台 Token 放进 `Authorization` 请求 `/api/admin/**`，也会因签名密钥不同而解析失败 → 返回 403；
后台 Token 同理不能当前台用户身份使用。

## 二、鉴权矩阵（`JwtAuthFilter`）

| 请求路径 | 要求 | 不满足时 |
|---|---|---|
| `/api/home`、`/api/culture/list|detail|categorys`、`/api/sentence/**` | 公开 | — |
| `/api/auth/send-code|register|reset|login|admin/login` | 公开（各自校验账号密码/角色） | 400 |
| `/api/auth/me`、`/api/auth/logout` | 前台 Token | 400/401 |
| `/api/auth/admin/me`、`/api/auth/admin/logout` | 后台 Token | 401 |
| `/api/admin/**`（含 `/api/admin/mail/**`） | 后台 Token **或** 后台 Session 管理员 | 未登录 401；已登录但非后台 403 |
| `/api/user/**`、`/api/culture/like|cancel/**` | 前台 Token **或** 已登录 Session | 401 |
| 其余 `/api/**` | 任意一种 Token 或 Session | 401 |

前台 Token 校验通过时只授予最小权限 `ROLE_FRONT_USER`，**不会**写入 Spring Security 会话；
后台 Token 校验通过时会加载角色/权限并桥接 Session，使原有 Thymeleaf 后台页面（`/admin/**`）继续可用。

## 三、关键代码

| 文件 | 作用 |
|---|---|
| `auth/service/JwtService.java` | 双密钥、`Scope{FRONT,ADMIN}`、按作用域解析并校验 `scope` |
| `auth/service/AuthService.java` | `login(account, password, scope)`：后台登录额外校验「管理员」角色 |
| `auth/controller/AuthController.java` | 前台/后台登录、当前用户、退出接口；后台登录建立 Security 会话 |
| `api/JwtAuthFilter.java` | 按路径 + 作用域鉴权；请求属性 `loginUserId`、`tokenScope` |
| `static/auth/js/api.js` | 双 Token 读写（`setToken` / `setAdminToken`）+ 旧 `token` 键清理 |
| `static/auth/js/login-auth.js` | 前台登录（跳首页或 `?redirect=`） |
| `static/auth/js/admin-login.js` | 后台登录（成功后进 `/admin`） |
| `controller/admin/RouterController.java` | `/toLogin` → `/static/auth/admin-login.html` |

## 四、配置（`application.yml`）

```yaml
app:
  jwt:
    front-secret: ${AUTH_JWT_FRONT_SECRET:...}   # 前台令牌密钥（生产必须注入随机值）
    admin-secret: ${AUTH_JWT_ADMIN_SECRET:...}   # 后台令牌密钥（与前台不同）
    front-expire-hours: 24
    admin-expire-hours: 8
```

> 升级注意：旧的单密钥 `app.jwt.secret` 已移除。历史 Token 由旧密钥签发，分离后必然校验失败，
> 前端 `api.js` 会主动清理旧的 `localStorage.token`，用户重新登录即可。

## 五、自测清单

```bash
# 1) 前台登录，拿前台 Token
curl -s -X POST http://localhost:8081/api/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"email":"admin@qq.com","password":"123456"}'      # scope=front

# 2) 用前台 Token 访问后台接口 -> 期望 403
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8081/api/admin/me \
     -H "Authorization: Bearer <前台Token>"

# 3) 后台登录，拿后台 Token
curl -s -X POST http://localhost:8081/api/auth/admin/login \
     -H 'Content-Type: application/json' \
     -d '{"email":"admin@qq.com","password":"123456"}'      # scope=admin

# 4) 后台 Token 访问后台接口 -> 期望 200
curl -s http://localhost:8081/api/admin/me -H "Authorization: Bearer <后台Token>"

# 5) 普通用户走后台登录 -> 期望 400「该账号不是管理员，无法登录后台」
```
