# 功能增强说明（第 1–4 批）

> 本次在「Vue3 前后端分离」改造之上，完成四批增强：安全加固、SEO 与检索、图片与阅读体验、
> 内容与治理。所有改动都保持**原有视觉不变**（新增 UI 一律使用组件内 scoped 样式）。

## 启用步骤（新增功能需要先建表）

```bash
# 1) 备份（脚本会备份 DB + 媒体 + 上传目录）
./scripts/backup.sh

# 2) 建表（纯新增、可重复执行；注意必须显式带库名）
mysql --no-defaults --default-character-set=utf8mb4 -uroot -p123456 culture_v2 < docs/sql/03_features.sql

# 3) 重启后端
./stop.sh && ./start.sh --no-db
```

`03_features.sql` 会创建：`biz_tag`、`biz_culture_tag`、`biz_comment`、`sys_operation_log`，
并追加 4 条后台菜单（内容治理 → 评论审核/标签管理；系统管理 → 操作日志）。

## 第 1 批 · 安全加固

| 问题 | 修复前（实测） | 修复后（实测） |
|---|---|---|
| 越权改他人头像 | 普通用户 `POST /file/uploadFile {id:1}` → **200 成功** | `{"isSuccess":false,"msg":"只能修改本人的头像"}` |
| 越权改任意文化封面 | 前台 Token `POST /file/uploadCultureFmFile {id:999999}` → **200 成功** | **403**（纳入后台鉴权闸门） |
| 上传无类型校验 | 只截后缀即落盘到公开静态目录，可传 `.html` → 同源存储型 XSS | 扩展名白名单 + 文件头内容嗅探，`evil.html` 被拒 |
| CORS 过宽 | `allowedOriginPatterns("*")` + `allowCredentials(true)` | 精确白名单，配置项 `app.cors.allowed-origins` |
| 详情无推荐位 | 前端只能取最新 4 条兜底 | `/api/culture/detail` 返回 `recommendCultures`（同分类优先、热门补齐） |
| 编辑用户清空昵称 | `editSaveUser` 直接 `nickname=#{nickname}` | `COALESCE(NULLIF(#{nickname},''), nickname)` |

头像上传的语义保持为「**本人或管理员**」：普通用户不传 id 即改自己；管理员可在用户管理里指定他人。

## 第 2 批 · SEO 与检索

**SEO**
- `GET /sitemap.xml`：动态生成（静态页 + 全部文化详情，含 `lastmod`），实测 36 条
- `GET /robots.txt`：`Disallow: /admin`、`/center`、`/api/`，并声明 sitemap 地址
- 每页 `title/description/canonical/OG/Twitter`；`/center` 等私有页 `noindex`
- 详情页注入 JSON-LD（`schema.org/Article`）
- 站点地址由 `app.site.base-url`（环境变量 `SITE_BASE_URL`）配置，默认 `http://localhost:8080`

**内容页预渲染（爬虫不需要执行 JS 就能拿到正文）**

- 工具：`web/tools/prerender.mjs` —— 读取 `/sitemap.xml` 得到待收录路由，用无头 Chrome 打开已构建的 SPA，
  等数据渲染完成后把 DOM 快照写成静态页：`dist/index.html`、`dist/culture/index.html`、`dist/culture/{id}/index.html`…
- 命令：`cd web && npm run prerender`（或 `npm run build:all` = 构建 + 预渲染）
- 快照里会剔掉运行时注入的 `<script src>`（客户端挂载时按需加载，避免重复执行），保留 CSS
- 托管层：Nginx `try_files $uri $uri/index.html $uri/ /front.html`；本机预览服 `serve-dist.mjs` 同样优先返回目录下的 `index.html`，
  未预渲染的路由（如 `/search`、`/admin/**`）继续走 SPA
- 实测（不执行 JS，直接 curl）：`/culture/1` 命中「故宫博物院」7 处；首页/列表/句子/关于均含正文标记；**36/36 路由预渲染成功**
- 发布后重建：`scripts/rebuild-static.sh`（构建 → 预渲染 → 重载 Nginx），可挂计划任务；后台改内容后建议每天重建一次
- ⚠️ **构建与预渲染必须成对执行**：`npm run build` 会生成新的 hash 资源，若不同步重跑预渲染，
  旧快照会引用已删除的 JS/CSS 而失效。直接用 `npm run build:all` 或 `scripts/rebuild-static.sh`。

> 选型说明：本次采用「无头浏览器快照」而非 vite-ssg/Nuxt。原因是 vite-ssg 需要把 6 个视图的数据获取改造到
> SSR 生命周期、并让 router 守卫在 Node 下不碰 `document`，还要改构建与部署链路；而本方案对现有代码
> **零侵入**，产物结构（每路由一个 `index.html`）与 vite-ssg 完全一致 —— 将来若切到 vite-ssg/Nuxt，
> Nginx 规则与重建脚本都不用改。

## 第 4 批 · 内容与治理

**标签**
- 表：`biz_tag` + `biz_culture_tag`（已带 6 个种子标签：博物馆/古建筑/非遗/书画/诗词/民俗）
- 公开：`GET /api/tag/list`、`GET /api/tag/cultures?tagId=&page=&pageSize=`
- 后台：`/api/admin/tag/list|save|delete`、`/api/admin/tag/culture?cultureId=`（回显）、`/api/admin/tag/bind {cultureId,tagIds[]}`
- 后台「标签管理」页可增删改；**文化新增/编辑弹窗新增标签多选框**，保存后自动绑定
- 前台详情页展示标签 chips（点击进入 `/tag/{id}` 聚合页）

**评论（含审核与 XSS 清洗）**
- 表：`biz_comment`（status：0 待审 / 1 通过 / 2 拒绝）
- 公开（只读）：`GET /api/comment/list?cultureId=`（只返回已通过，两级树）
- **提交必须登录**：`POST /api/comment/submit` 需要前台 Token；未登录返回 **401**，
  前端此时不渲染表单，而是提示「登录后才能留言 / 去登录」（带 `?redirect=` 回跳当前页）
- **署名以服务端为准**：昵称取账号资料的 `nickname`（无则 `username`），邮箱取账号邮箱；
  请求体里即使传 `nickname`/`email` 也会被忽略（已实测：伪造值不落库）
- 后台：`/api/admin/comment/list|pending|audit|delete`，对应「评论审核」页
- 安全：入库前经 `com.culture.util.HtmlSanitizer` 白名单清洗（标签/属性/协议三重白名单），
  昵称纯文本化，同一 IP 60 秒限一次（Redis）
- 实测：提交 `<img src=x onerror=alert(1)>你好<script>alert(2)</script>` → 库中仅存 `你好`；
  待审不可见 → 审核通过后前台可见

**操作日志（审计）**
- 表：`sys_operation_log`；`OperationLogInterceptor` 自动记录 `/api/admin/**` 的 POST/PUT/DELETE
- 后台「操作日志」页支持按模块/关键词查询
- 已知限制：JSON body 在拦截器阶段已被消费，`targetId` 依赖控制器 `request.setAttribute("oplogTargetId", id)`；
  且控制器自行 catch 业务异常时 `success` 仍记为 1。模板/文化等模块如需精确目标 id，补一行 setAttribute 即可。

**备份**
- `scripts/backup.sh`：DB（mysqldump）+ `upload/media` + `frontend/static/upload`，生成 MD5 清单与恢复说明，按 `KEEP_DAYS`（默认 14 天）清理
- 实测产物：`backups/20260910_224017/`（db 124K + upload 6.8M）

## ⚠️ 部署到其它环境时的两个必做项

1. **必须执行建表脚本**（否则标签/评论/日志相关接口报错）：
   `mysql --no-defaults --default-character-set=utf8mb4 -uroot -p123456 <库名> < docs/sql/03_features.sql`

2. **新增菜单必须同时有权限与授权**——后台侧边栏由
   `sys_user_role → sys_role_permission → sys_permission(menu_id) → sys_menu` 关联查询得出，
   **只插 `sys_menu` 不会显示**。脚本第 6 节已包含：
   - `sys_permission`：`comment:audit`(menu 102)、`tag:manage`(menu 103)、`oplog:list`(menu 104)
   - `sys_role_permission`：把上述权限授予「管理员」(role_id=1)
   如果给其它角色也开这些菜单，需要再补对应角色的 `sys_role_permission`。

> 另外：浏览器可能缓存旧的入口 HTML，导致「菜单是新的、点击却没反应」。
> 本机预览服已对 HTML 加 `Cache-Control: no-cache`（`assets/` 下的 hash 产物仍长缓存）；
> 若用 Nginx，请确认 `nginx.conf.example` 里的入口 HTML 不缓存配置已生效。遇到怪现象先 **Ctrl+F5**。

## 遗留与后续建议

1. `%`/`_` 由 LIKE 处理，数据量大时建议改 MySQL FULLTEXT（中文需 ngram 分词器）。
2. 预渲染已接入（见上文「内容页预渲染」）。若内容更新频繁、希望免重建，再考虑换 Nuxt SSR。

# 优化与增强说明（第 5 批：性能 / 工程化 / 体验 / 运维安全）

## 一、交互体验（本轮用户明确要求的两项）

### 1) 顶部居中轻提示（替代 jconfirm「温馨提示」）
- 新增 `web/src/components/ToastHost.vue` + `web/src/utils/notify.js`，顶部居中、可堆叠、自动消失、
  鼠标悬停暂停计时；成功/失败/警告/信息四种语义色，最多同时 5 条（超出丢弃最早）。
- **老代码零改动接入**：`installLegacyNotifyShim()` 接管了 `$.confirm` / `$.alert`，规则是
  「单按钮（纯告知）→ 顶部提示；双按钮 → 新确认弹窗」。因此 56 处历史调用自动获得统一交互。
- `loadScript` 每次动态加载脚本后会重新接管一次：老页面会动态引入自带 jQuery 的脚本
  （如详情页的 jquery-1.11.1），会替换全局 jQuery，一次性安装会失效。

### 2) 二次确认（删除等破坏性操作）重新设计
- 新增 `web/src/components/DialogHost.vue` + `confirmDelete()/confirmDialog()`：
  红色主按钮 + 危险图标、「不可恢复/影响范围」独立提示行、**默认聚焦「取消」**（防回车误删）、
  危险弹窗点遮罩不关闭、Esc 取消、Enter 确认、`onConfirm` 返回 Promise 时按钮进入 busy 态。
- 破坏性入口全部改成带对象名与影响说明的确认：文化、分类、公告、句子、标签（单个/批量）、评论（单个/批量）、用户（批量）。
- `confirmDialog` 取消时 **resolve(false)**（不是 reject），避免调用方 `await` 抛未捕获异常。

## 五、运维与安全

- `GET /api/health`：DB/Redis/磁盘状态 + 运行时长，依赖挂掉也返回 200（用 status 表达），不引入 actuator。
- `POST /api/client-error`：前端未捕获异常/未处理 Promise 拒绝上报（每会话最多 5 条，Redis 按 IP 限流 20/分钟）。
- 登录失败锁定：同邮箱 15 分钟内失败 5 次锁 10 分钟（Redis，Redis 不可用时降级为不锁定）。
- JWT 滑动续期：剩余有效期不足一半时通过 `X-Refreshed-Token` 下发新 Token，前端静默替换。
- 安全响应头：`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy`
  （不加 CSP：页面存在内联脚本）。
- Druid 慢 SQL 日志：`log-slow-sql` + `slow-sql-millis: 1000`。

## 六、本轮修复的两个「隐蔽 bug」（值得记住）

1. **预览服 gzip 缓存 key 不含 mtime**：重新构建后 HTML 只换了资源 hash、长度完全相同，
   旧 key 命中就返回**过期 HTML**，浏览器去请求已删除的 chunk → 页面静默挂不起来、预渲染 0/36。
   修复：key 改为 `路径 + mtime + 长度`。
2. **`/assets/**` 缺失时回退成 HTML**：浏览器会把 HTML 当模块脚本解析，报 MIME 类型错误；
   真因往往只是「构建产物与预渲染快照不同步」。修复：`/assets/**` 直接 404，并给出重建提示。

## 十、⚠️ 本轮的坑与口径（务必知道）
1. `docs/sql/03_features.sql` 的 7 条 `INSERT ... SELECT ... WHERE NOT EXISTS` 补了 `FROM DUAL`，

5. 标签合并**不可逆**（关联已改挂，无法区分原属谁）；源标签恢复也不会带回关联。
6. 全文检索依赖 ngram 索引，**没执行 `10_search.sql` 也能跑**（自动降级 LIKE），只是性能回到 LIKE。

# 第 8 批：搜索服务端筛选 / 公共列表缓存 / 慢 SQL 上报 / 表格 Vue 化收尾

## 一、搜索组合筛选「服务端化」（分类 / 标签 / 时间）

以前三个筛选条件只能在前端做（把候选池放大到后端上限 50 条再本地过滤），
结果就是「命中但没进候选池的内容搜不到」。本轮把它变成真正的服务端筛选：

- 后端 `GET /api/search` 新增 4 个**可选**参数：
  - `categoryId` → `biz_culture.category_id`（只作用于文化结果）；
  - `tagId` → `biz_culture_tag` 关联，用 `exists` 相关子查询而不是 `join`
    （一条内容多个标签时 `join` 会让同一行出现多次，`count(*)` 虚高、分页重复）；
  - `startTime` / `endTime` → `created_at` **闭区间**，只给日期时 `endTime` 按当天 `23:59:59` 处理
    （否则 `startTime=endTime=同一天` 会因为记录带时分秒而永远 0 条）。
- **非法参数一律「忽略该筛选」而不是 400/500**（对齐接口既有容错风格：`type` 非法按 all、`page<1` 按 1、
  `pageSize>50` 按 50）。为此 Controller 刻意用 `String` 接参自己解析——若直接声明 `Long`，
  `?categoryId=abc` 会在 Spring 参数绑定阶段抛异常，那就变成 400 了。
- 筛选条件在 Mapper 里抽成**一个共用片段**（`SEARCH_FILTER_SQL` / `SEARCH_TIME_FILTER_SQL`），
  4 条文化语句（LIKE/全文 × 总数/列表）全部拼接它 → 总数与列表口径**逐字相同**，不可能对不上；
  全文路径异常降级 LIKE 时筛选参数原样带上。
- 时间筛选用**规范化字符串**而不是 `date_format(created_at,...)`：后者把列包进函数会让索引失效、
  必然全表扫描；前者 MySQL 只把常量侧解析成 DATETIME（不做时区换算），实测仍走
  `idx_culture_deleted_created`（`type=range`），分类走 `idx_culture_category`，标签子查询走 `uk_culture_tag`。
- 前端 `SearchView.vue` 相应重写：去掉「标签反查内容 id 集合 + 本地过滤 + 候选池放大」那一整套，
  下拉变化只写 URL query，由 watcher 带新参数重新请求；总数就是服务端总数（全量口径）。
  句子表没有分类/标签字段（后端有意忽略这两个参数），所以选中分类/标签时**句子区整块隐藏**并给出说明，
  避免「句子没被过滤」的错位感。

## 二、前台公共列表的 Redis 读缓存（分类 / 标签）

- 新增 `CacheService`（显式 `getOrLoad` / `evict`，不用 `@Cacheable`，原因见类注释）：
  只缓存两个「与登录用户无关、读多写极少」的前台接口
  `GET /api/culture/categorys`、`GET /api/tag/list`（含 `cultureCount`）。
- **后台的同类接口有意不走缓存**：管理员改完必须立刻看到最新数据。
- 失效两道保险：① 所有写路径主动删 key（分类增删改/恢复；标签保存/删除/批量删除/恢复/
  设置内容标签/合并/改名）；② TTL 兜底（`app.cache.ttl-seconds`，默认 60 秒）。
- **失败一律降级**：Redis 未配置 / `app.cache.enabled=false` / 序列化异常 / 连接断开 —— 都只是
  「这次不走缓存」，直接查库，绝不因缓存影响接口（读失败还会顺手删掉脏 key）。
- 空结果也占位（存空串），避免空列表每次都穿透回源。

## 三、慢 SQL 上报（MyBatis 插件 + Prometheus 指标）

- 新增 `SlowSqlInterceptor`：只做「计时 + 记日志 + 计数」，不改 SQL、不改参数、不吞异常。
  超过 `app.slow-sql.threshold-ms`（默认 500ms）打 WARN（statement id + 耗时 + 占位符 SQL，已截断）。
- `/api/metrics` 新增 `culture_slow_sql_enabled / _threshold_ms / _total / _max_ms / _last_ms`，
  最近一次慢语句以注释行输出（不进 label，避免标签基数膨胀）。
- 与 Druid 的 `druid.stat.slowSqlMillis=1000` 是两套独立口径：Druid 只有日志、没有计数，
  这里阈值更小，是为了在「本该毫秒级」的内容站更早发现退化的查询。
- 新增配置项：`APP_CACHE_ENABLED` / `APP_CACHE_TTL_SECONDS` / `APP_SLOW_SQL_ENABLED` /
  `APP_SLOW_SQL_THRESHOLD_MS`（`.env.example` 已同步）。

## 五、顺手修掉的一个「假红」：e2e 前台登录的冷启动抖动

- 现象：刚刚重启后端就跑全量回归时，`e2e-check` 偶发 43/47 —— 前台登录那一步拿不到 token，
  连带「跳转干净路径」「双 Token 隔离（403）」一起红；隔几分钟再单独跑又是 47/47。
- 定位：本轮新增的慢 SQL 上报直接把证据打在了日志里 —— 冷启动第一次登录时
  `UserMapper.findByEmail` 单次 **2441ms**（紧接着 Spring Security 生成会话 ID 又要 208ms），
  而套件原来只固定睡 3 秒就断言。
- 处理：套件改为「提交 → 轮询等 token（最多 8 秒）→ 仍没有就重试一次」，并在详情里报告提交次数；
  同时把 403 断言加上「前台 Token 确实存在」的前提（否则退化成拿 `Bearer null` 请求，
  状态码取决于会话兜底，会给出误导性的 200/403）。
- 结论：这是**测试的时序问题，不是登录功能回归**；修完后连续多次单跑与全量跑均 47/47。

## 六、后台侧边栏（目录）视觉修复与优化

用户反馈「后台目录样式也可以优化」，排查后发现不只是不好看，而是**老主题留下的三个视觉 bug**：

1. `.coder-layout-sidebar` 在老主题里是 `background-color: red; background-image: url("../images/bg.jpg")`
   —— 占位红底 + 一张 711KB 的背景图；
2. 同一个块上还有 `opacity: .8`（`.sidebar-header` 上还带一段内联 `opacity:.9; filter:alpha(opacity=90)`）；
3. `.coder-layout-sidebar-scroll` 的 `background-color: rgba(33,56,65,.82)` 同样是半透明。

三者叠加的结果：240px 宽的侧边栏其实是**半透明**的，页面正文、表格与封面图会直接透到目录文字上
（截图里能看到菜单后面糊着内容）。本轮的处理（`web/src/styles/admin-ui.css` 的「侧边栏（目录）视觉优化」段 +
`AdminLayout.vue` 去掉头部内联 opacity）：

- 外壳：`opacity: 1`、`filter: none`、显式深色渐变底 `#2c3d47 → #22303a` + 右侧投影，与内容区拉开层次；
- **布局（左固定导航 + 右内容区）**：侧边栏是 `position: fixed`，**不占布局空间**，内容区靠 `padding-left` 让位。
  老主题写的是 `padding-left: 240px`，而本次改样式时用了 `padding: 18px 20px 26px` 简写，把 left 覆盖成 20px
  → **内容滑到固定导航底下被遮住**（用户反馈的「导航栏把内容区内容遮住了」）。现改为
  `padding: 18px 20px 26px 260px`（240 侧边栏 + 20 留白），并补上折叠态 `.coder-layout-sidebar-close .coder-layout-content{padding-left:20px}`；
  窄屏断点与老主题对齐为 **1024px**（此时侧边栏是抽屉，不再占位，内边距 12px）；
- **目录不加图标**：按用户要求去掉一级/二级项（含「后台首页」）的 `<i class="mdi ...">`，
  文字左内边距一级 20px、二级 34px，右侧仍保留主题自带的展开箭头；
- 布局：外壳改为 flex 纵向三段（品牌 68px / 滚动目录 / 底部入口），**底部「打开前台站点」移出滚动区**，
  目录再长也不会把它挤走（滚动区要 `min-height: 0` 才会正确出现滚动条，这是 flex 滚动的经典坑）；
- 一级目录：行高 44px、文字对齐、悬停淡底 + 展开中的分组父项高亮；
- 二级目录：做成「内嵌面板」（半透明底 + 左侧引导线），子项 36px，激活时左侧 3px 强调色亮条 + 白字；
- 滚动条：细滚动条（`scrollbar-width: thin` + `::-webkit-scrollbar-thumb`），深色底上不再出现系统灰条。

**刻意的约束**：只改外观，不动任何结构 class —— `.coder-layout-sidebar`、`.nav-item-has-subnav(.open)`、
`#nav_*`（父级）、`#id_*`（子项）、`body.coder-layout-sidebar-close` 都是主题脚本与回归套件的钩子；
改完 debug-menu / click-all-menus / click-seq / ui-check / e2e 全部仍然通过。
