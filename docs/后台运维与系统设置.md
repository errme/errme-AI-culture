# 后台运维工具与系统设置

> 本轮把 **Druid 监控**、**API 文档（Swagger）** 接入后台，并把原先只能改配置文件的
> 可变项搬进 **后台「系统设置」** 页面。核心原则：**不写死** —— 路径、开关、配置项、
> 校验范围都由配置或数据库驱动，前端不维护任何对照表。

---

## 一、Druid 监控页

### 1.1 为什么之前被移除、现在又能接回来

Spring Boot 3 用 `jakarta.servlet`，而 Druid 的
`com.alibaba.druid.support.http.StatViewServlet` 是 **javax** 实现，挂上去会在启动时抛
`NoClassDefFoundError` —— 上一轮升级时因此把监控页摘掉了。

准备重新接入时实测发现：**Druid 自 1.2.25 起提供了 jakarta 变体**，只是换了包名：

| | 包名 | 适用 |
|---|---|---|
| javax 版 | `com.alibaba.druid.support.http.StatViewServlet` | Spring Boot 2 |
| **jakarta 版** | `com.alibaba.druid.support.jakarta.StatViewServlet` | **Spring Boot 3** |

因此把 Druid 从 1.2.24 升到 **1.2.28**（1.2.24 的 jar 里没有这个包，已实测确认），
`DruidConfig` 改用 jakarta 包下的 `StatViewServlet` / `WebStatFilter`，监控页即可正常挂载。

### 1.2 配置项（全部走环境变量，不写死）

| 配置项 | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `app.druid.stat.enabled` | `DRUID_STAT_ENABLED` | `true` | 是否注册监控页；关闭时 Bean 仍在但不映射 URL |
| `app.druid.stat.path` | `DRUID_STAT_PATH` | `/druid/*` | 访问路径 |
| `app.druid.stat.user` | `DRUID_STAT_USER` | `admin` | 监控页账号 |
| `app.druid.stat.password` | `DRUID_STAT_PASSWORD` | **无** | **必填且 ≥8 位**，否则启动失败 |
| `app.druid.stat.allow` | `DRUID_STAT_ALLOW` | 本机 + 内网网段 | 来源 IP 白名单 |
| `app.druid.stat.reset-enable` | `DRUID_STAT_RESET` | `false` | 是否允许在页面上重置统计 |
| `app.druid.stat.uri-monitor` | `DRUID_STAT_URI_MONITOR` | `true` | 是否开启 URI 监控 |

### 1.3 安全设计

监控页有**两层**保护，都来自配置：

1. Druid 自带登录（口令只从环境变量读，**刻意不设默认弱口令**，缺失就直接拒绝启动）；
2. 来源 IP 白名单。

它同时暴露 SQL 统计等敏感信息，**生产环境建议保持默认关闭**，排查时临时开启、排查完关掉。
另可在 Nginx 再加一道内网限制（`deploy/nginx.conf.example` 里有现成配置，默认注释）。

## 二、API 文档（Swagger UI）

用 **springdoc-openapi 2.8.4**（2.x 对应 Spring Boot 3.x）替代原来的 springfox 2.9.2
（后者不支持 SB3，已在上一轮删除）。

| 配置项 | 环境变量 | 默认 |
|---|---|---|
| `app.api-doc.enabled` | `API_DOC_ENABLED` | `true` |
| `app.api-doc.ui-path` | `API_DOC_UI_PATH` | `/swagger-ui.html` |
| `app.api-doc.api-docs-path` | `API_DOC_JSON_PATH` | `/v3/api-docs` |
| `app.api-doc.title` / `description` / `version` | — | 见 application.yml |

文档里已内置 **「前台Token / 后台Token」两套 SecurityScheme**（对应项目的双密钥 + 双 scope），
在 Swagger UI 右上角 Authorize 填令牌即可直接调试，不用手工拼 `Authorization` 头。

实测：`/v3/api-docs` 输出 OpenAPI 3.1.0，覆盖 **110+ 个接口**。

## 三、"集成到后台"是怎么做的（关键：不把路径写死在前端）

新增 **`GET /api/admin/devtools`**：由后端按**当前生效配置**输出工具清单：

```json
[
  { "key": "druid",   "name": "数据库监控", "url": "/druid/",          "newTab": true },
  { "key": "apidoc",  "name": "API 文档",   "url": "/swagger-ui.html", "newTab": true },
  { "key": "metrics", "name": "运行指标",   "url": "/api/metrics",     "newTab": true }
]
```

后台侧边栏据此渲染「运维工具」区。

**为什么不直接把 `/druid/`、`/swagger-ui.html` 写进前端菜单**：这两个路径是可配置的。
写死之后，运维一旦改了 `app.druid.stat.path` 或 `app.api-doc.ui-path`，菜单就会指向 404。
现在改配置 → 菜单自动跟随，两端不会不一致；关闭的工具也不会出现在清单里。

## 四、系统设置（sys_config）

### 4.1 解决了什么

原先这些参数只能改 `application.yml` 再**重启服务**，其中接口限流阈值更是**硬编码在
`RateLimitInterceptor` 的静态 Map 里**：

| 分组 | 配置项 |
|---|---|
| 站点信息 | `site.name`、`site.base-url`、`site.description` |
| 验证码策略 | `code.expire-minutes`、`code.resend-seconds` |
| 登录有效期 | `jwt.front-expire-hours`、`jwt.admin-expire-hours` |
| 缓存 | `cache.enabled`、`cache.ttl-seconds` |
| 上传限制 | `upload.max-image-mb`、`upload.max-video-mb` |
| 接口限流 | `limit.search/export/purge/rollback/permission-per-minute` |

现在全部收进 **`sys_config`** 表，由后台「系统设置」页维护，**改完即时生效、无需重启**。

### 4.2 读取策略（配置中心不能成为新的故障点）

```
内存缓存优先 → 缓存没有该键 → 回退到 application.yml 的默认值
```

因此「表不存在 / 少了某一行 / 数据库暂时不可用」都**不会导致服务不可用**，只会退回改造前的行为。
即使还没执行建表脚本，服务照常启动（日志里会有一条 WARN）。

### 4.3 校验规则也在数据里

配置表的 `value_type`（string/int/bool）与 `min_value` / `max_value` 决定校验方式与前端控件类型，
**范围写在数据库里而不是代码里**，改范围只需改数据。实测报错信息会带上数据库里的中文名与范围：

```
配置校验未通过 —— 验证码有效期（分钟）：不能大于 1440
配置校验未通过 —— 站点域名：结尾不要带斜杠（拼接时会产生 // ）
```

写入是**先整体校验、再统一落库**，任一不合法则整批拒绝，不会出现「改了一半」的中间状态。

### 4.4 与启动期配置的边界（刻意不放进数据库）

端口、数据源、Redis、上传目录，以及 **Druid / API 文档的开关与路径**，
都在 Spring 容器启动阶段就要用到（Druid 本身还依赖数据源），放进数据库会形成**循环依赖**。
这类参数继续由 `application.yml` + 环境变量管理。

### 4.5 新增配置项怎么做

只改数据库，**前后端都不用改**：

```sql
INSERT INTO sys_config (config_key, config_value, value_type, config_group, label, description, default_value, min_value, max_value, sort)
VALUES ('xxx.yyy', '1', 'int', 'common', '中文名', '说明', '1', 1, 100, 10);
```

页面会自动出现这一项（分组名与顺序也来自数据库）。

## 五、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/devtools` | 运维工具清单（按当前配置输出） |
| GET | `/api/admin/config/list` | 全部配置项（含分组、类型、范围、说明、最后修改人） |
| POST | `/api/admin/config/save` | 批量保存 `{ values: { key: value } }` |
| POST | `/api/admin/config/reset` | 恢复某项为出厂默认 `{ key }` |
| POST | `/api/admin/config/reload` | 从数据库重新载入缓存（供「直接用 SQL 改过值」的场景） |

均需后台令牌 + 管理员角色。

---

## 六、前端改动的两点

1. **侧边栏「运维工具」区**：清单来自 `/api/admin/devtools`，不写死路径；
2. **`routeOf()` 支持直接写 SPA 路径**：菜单表里可以直接写 `/admin/settings`，
   `AdminLayout` 原样采用。这样**新增后台页面只需往 `sys_menu` 插一行，不需要改前端代码** ——
   旧实现只认 `MENU_ROUTE_MAP`，等于每加一个页面都要来前端加一条映射。

## 七、上线步骤

```bash
# 1) 执行配置与菜单脚本（幂等，可重复执行；已存在的键不会被覆盖）
mysql --no-defaults --default-character-set=utf8mb4 -uroot -p123456 culture_v2 < docs/sql/13_sys_config.sql

# 2) 配置 Druid 监控页口令（启用监控页时必填，≥8 位）
export DRUID_STAT_PASSWORD='你的强口令'

# 3) 构建（注意 clean；用 wrapper 保证 Maven 版本）
cd backend && ./mvnw -DskipTests clean package
cd ../web && npm run build
```

生产环境建议：`DRUID_STAT_ENABLED=false`、`API_DOC_ENABLED=false`，
或按 `deploy/nginx.conf.example` 里的示例把它们限制为仅内网可访问。
