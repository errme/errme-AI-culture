## 二、Bug 修复（用户报障）

### 2.1 用户删除「点了没反应」
- **根因**：`UserMapper.xml` 的 `whereSql` 漏了 `u.deleted = 0`。删除接口本身正常（逻辑删除置 1），
  但列表与统计 SQL 没过滤该字段 → `refreshList()` 拉回来的数据和删除前一模一样，界面无变化。
  其它模块（Culture/Category/Sentence/Announcement）都有这个条件，UserMapper 是唯一遗漏的。
- **实测**：修复前 `total=1` 且行仍在；修复后 `total=0`、行消失。
- **顺带**：`queryAll`（Excel 导出）补上同样过滤。

### 2.2 新增用户永远失败（排查删除时发现）
- **根因**：`User.password` 用了 `@JsonIgnore`，而 Jackson 的 `@JsonIgnore` **同时屏蔽序列化与反序列化**
  → 前端提交的密码根本绑定不到实体 → BCrypt 抛 `rawPassword cannot be null`。
- **修复**：改为 `@JsonProperty(access = WRITE_ONLY)`（允许入参、不出现在任何响应里）。
- **实测**：新增成功；响应字段列表中不含 `password`；新账号可正常登录。

### 2.3 删除交互完善
- `refreshList()` 改为返回 Promise，删除后**先等列表刷新完成再弹成功提示**；
- 失败时不再 `.catch` 吞掉异常，而是提示后重新抛出，让确认弹窗按失败收尾；
- 提示文案带上被删对象名；批量删除失败时也先刷新列表，反映「部分成功」的真实状态。

### 2.4 回归测试补强
`delete-check.mjs` 的用户用例原本「只验证弹窗、点取消不留副作用」，**从不真正删除** ——
这正是 Bug 2.1 长期没被发现的原因。现改为与其它模块一致的完整链路
（造账号 → 真实删除 → 断言「行消失 + 接口已删」）。

## 三、UI / UX 修复

### 3.1 主内容区被顶栏遮挡 50px
- **根因**：`admin-ui.css` 用 `padding: 18px 20px 26px 260px` **简写**，把老主题的
  `padding-top: 68px` 一并冲成 18px；而 `.coder-layout-header` 是 `position:fixed`（不占布局空间），
  内容区只能靠 padding-top 让位。
- **实测**：1440px 视口下 header 高 68px、content padding-top 18px → **overlap = 50px**（≤1024px 断点 54px）。
- **修复**：新增 `--ad-header-h: 68px`（六档视口实测恒定），改用 longhand 明确写各方向，
  桌面 68+18=86px、窄屏 68+14=82px。**实测 overlap 由 +50/+54 变为 -18/-14**。

### 3.2 二次确认弹窗动画卡顿
- **根因**：`DialogHost` 的遮罩是 `position:fixed; inset:0` 且参与 opacity 过渡，
  同时带 `backdrop-filter: blur(2px)` —— 每一帧都要对整屏背景重做一次模糊合成。
- **修复**：移除该 `backdrop-filter`（2px 模糊视觉收益极小），遮罩 0.45→0.5 补偿，
  卡片加 `will-change: transform, opacity`。
- **顺带**清理另外两处「背景接近不透明、模糊几乎不可见」的 backdrop-filter：
  ToastHost（0.95 不透明）与 `.ad-sticky-actions`（0.94 且是 sticky，滚动时每帧重算）。

## 四、安全修复

| 问题 | 影响 | 修复 |
|---|---|---|
| **越权导出用户表** | `/user/downloadExcel` 不在 `/api/` 前缀下，被鉴权过滤器跳过；任何前台注册用户都能下载全站用户（姓名/邮箱/电话） | 迁到 `/api/admin/user/export`，纳入统一鉴权 + 显式管理员校验。实测：前台 403 / 后台 200 / 无 token 401 |
| **存储型 XSS** | 后台文化 `desc`/`info` 完全不清洗，前台用 `v-html` 渲染；拥有内容编辑权限的角色可写入 `<img onerror>` 在所有访客浏览器执行 | 服务层统一清洗：`desc` 转义为纯文本、`info` 走**富文本白名单**（保留图片/表格/视频嵌入与对齐字号颜色，丢弃全部脚本与事件属性） |
| **jQuery 全局污染** | 文化详情页加载 1.11.1 后不还原，导致整个 SPA 的 `window.$` 永久降级 → 3.4.1 注册的监听器无法解绑、持续泄漏 | 抽出 `utils/legacyJq.js`，加载后 `noConflict(true)` 隔离；带「仅在确实换过实例时才隔离」的守卫 |
| **log4j 1.2.17 / Spring Boot EOL** | 已知 CVE + 无维护 | 随 SB3 升级一并移除 |

## 六、结构与工程化

- **前端自包含**：`frontend/static/{index,admin,auth}` → `web/public/`，URL 完全不变；
  `cd web && npm run build` 即为完整可部署产物（220 个文件 git 识别为重命名，历史保留）。
- **运行时数据收敛**：头像/封面迁到 `upload/{avatar,culture}`，与 `upload/media` 语义一致
  （都是运行时数据、都由 `backup.sh` 备份、都被 `.gitignore` 排除）。
- **构建可复现**：新增 Maven Wrapper（`backend/mvnw` 锁定 3.9.16）——
  SB3 要求 Maven ≥ 3.6.3，而开发机 PATH 上是 3.6.1；CI 改为只装 JDK。
- **部署链修复**：`docker-compose` 原先有两处必然失败（root 路径与挂载点不匹配 → 静态全 404；
  `proxy_pass 127.0.0.1:8081` 在容器内指向 nginx 自身 → 接口全挂），
  且 CI 从不启动该容器所以一直没暴露。已拆分 `deploy/nginx.conf.example`（裸机）
  与 `deploy/nginx.docker.conf`（容器）；删除损坏的 `web/nginx.conf.example`。
- **备份脚本 Bug**：`verify-backup.sh` 查找 `backups/*.sql`，实际产物在 `backups/<时间戳>/`
  → 演练永远报「找不到备份」；第 4 步校验媒体包同样 glob 错，且校验的是「任意一个」包
  而非本次备份集。均已修复并实跑通过。
- **新增 `.dockerignore`**：避免把 `target/`（86MB+）当构建上下文上传。

## 七、遗留事项（未做，供后续排期）

以下为已知但本轮未处理的问题，按建议优先级排列：

1. **`e.getMessage()` 直接返回前端（69 处）**：可能泄露表名/索引名等数据库细节。
   其中相当一部分是 `BusinessException` 的**有意提示文案**（改了会破坏 UX），
   需要逐个甄别，不适合批量替换。建议后续引入 `@RestControllerAdvice` 逐步收敛。
2. **16 份重复的 `isAdmin()`**：分布在 16 个控制器，均为
   `roleService.listRoleByUserId()` + 硬编码中文角色名「管理员」。
   建议抽 `AdminGuard` 组件（并可复用已加载的 authorities，免掉一次查库）。
3. **`PermissionServiceImpl` 的循环插入**：授予菜单权限时逐条 insert
   （规模受菜单数量限制，影响远小于已修复的两处 N+1）。
4. **`/api/metrics` 完全公开**：暴露连接池/JVM/慢 SQL 指标（仅聚合数字，无业务明细）。
   监控需要它匿名可读，如需收紧可加内网白名单。
5. **缩略图按需生成用全局 `synchronized`**：一张大图解码会阻塞其它线程的缩略图生成。
   建议锁粒度降到单文件。
6. **Sitemap 每个分片请求都全量查询 + 内存排序**（无服务端缓存，只有响应头缓存）。
7. **推荐路径 `getUserTjCulture` 是死代码**：协同过滤从未被调用，详情页「猜你喜欢」
   实际走「同分类 + 热门兜底」。Mahout 已换成等价 SQL 实现并保留，若将来要启用需先接入调用方。
8. **`UserDetailsServiceImpl` / `UserSecurity` 已无实际调用方**（Session 桥接移除后失去用途）。
9. **测试并发健壮性**：8 个套件用 `--parallel 4` 同时跑时，多个 headless Chrome 争抢资源会
   偶发 `ECONNREFUSED 127.0.0.1:91xx` 误判失败；逐个运行均通过。建议降低默认并发度或加端口随机化。
10. **前端仍有 5 个后台列表页复制粘贴同一套表格壳**（约 500 行/页），
    建议抽 `useCrudTable` composable 与 `AdTable`/`AdPager`/`AdDialog` 组件。

## 八、如何验证

```bash
# 1) 起依赖与服务
./start.sh --no-db            # 或 ./start.sh

# 2) 后端构建（必须带 clean；用 wrapper 保证 Maven 版本）
cd backend && ./mvnw -DskipTests clean package

# 3) 前端构建
cd web && npm run build

# 4) 端到端回归（8 套；建议分批跑，全量顺序约 8 分钟）
node web/tools/verify.mjs                       # 顺序全量
node web/tools/verify.mjs --parallel 3 --fast   # 只跑最关键的 3 套
SKIP=feature-check,delete-check,e2e-check node web/tools/verify.mjs --parallel 4   # 跑其余

# 5) 后端零依赖自测
cd backend && ./mvnw -q -DskipTests compile dependency:build-classpath -Dmdep.outputFile=target/cp.txt
javac -encoding UTF-8 -d target/test-classes -cp "target/classes:$(cat target/cp.txt)" src/test/java/com/culture/SelfTest.java
java -Dfile.encoding=UTF-8 -cp "target/classes:target/test-classes:$(cat target/cp.txt)" com.culture.SelfTest
```
